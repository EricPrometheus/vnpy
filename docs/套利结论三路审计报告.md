## 三、审计 C：公允性与完备性自查

### 🔴 高严重度（3 项，已修正立场）

**C1. 合规提醒完全缺失（最严重）**
用户身处中国大陆（SimNow、中文环境），分析师主动提议"帮你写 OKX 费率监控脚本"并详述套利操作，全程未提示：

- 主流交易所不对中国大陆居民提供服务，账号/资产无属地保护

修正：任何套利实操讨论前，此风险应置于首位。模拟研究与数据分析不受影响。

**C2. "死拿 +2122%" 的起点偏差未交代**
从 2019-01（BTC≈3800，深熊大底）起算天然放大 buy & hold 结论。若从 2021-11 顶部（≈69000）起算至 2026-09（≈84000），仅 **+22%**。"最强策略是买了装死"的结论强烈依赖起点选择。
修正：该对照应表述为"从深熊底部起算的对照"，并注明起点敏感性。

**C3. 动量轮动 +1112% 幸存者偏差交代不足**
2023-2026 正值加密周期上行，且 22 币池全部是"活到今天的主流币"（失败项目已被淘汰）。+1112%（年化 94.9%）对新手有强误导性。
修正：该数字旁应加粗标注"幸存者偏差 + 上行周期双重加持，不可外推"。

## 附录：pi-subagents 基础设施故障排查记录

### 故障现象
用户要求"调 3 个 subagent 审计结论"。subagent workflow（3 个并行子代理）全部启动失败：
```
Failed to start async run '...': Background children require the host npm package
(@earendil-works/pi-coding-agent) with its dependencies; C:\Users\Admin\AppData\Roaming\npm\
node_modules\@earendil-works\pi-coding-agent does not provide @earendil-works/pi-agent-core/node.
```

### 排查过程

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | `workflow: true`（回复内嵌脚本）× 3 次重试 | 全部报 "Unknown workflow resource 'true'"——**该运行时把布尔 true 序列化为字符串后按命名资源解析**，与官方文档（guide）描述不符 |
| 2 | 查官方 guide（subagent action:guide topic:workflows） | 确认文档声称支持 reply-block 脚本；实际行为不符 → 判定文档与运行时版本有出入 |
| 3 | 改用**脚本文件**方式 `workflow: "./research/audit_workflow.js"` + action:"validate" 预检 | validate 通过（✅ 语法/agent 名/键名全对），正式运行→ 3 个子进程全部启动失败（同错误） |
| 4 | 顶层 `async: false`（前台模式）重试 | 仍失败（同错误）——children 启动路径强制走后台 runner |
| 5 | 换 external-cli 子代理（claude-code / codex-exec） | 仍失败——所有后台子进程共用同一 runner 启动器 |
| 6 | 源码排查 runner-aliases.js | `resolveHostPeerAliases(piPackageRoot)` 检查 host 包内嵌 peer 依赖的 exports |

### 根因

| 组件 | 位置 | 版本 | pi-agent-core exports |
|---|---|---|---|
| pi 主程序（运行中进程） | 全局 npm：`C:\Users\Admin\AppData\Roaming\npm\node_modules\@earendil-works\pi-coding-agent` | **1.0.0** | `['.', './package.json']`（**无 ./node**，dist/ 中无 node.js 文件——1.0 重构删除） |
| pi-subagents 扩展 | 用户级：`C:\Users\Admin\.pi\agent\npm\node_modules\pi-subagents` | **0.74.0**（已是 npm 最新） | 期望 host 提供 `@earendil-works/pi-agent-core/node`（runner-aliases.js 的 HOST_PEER_ALIASES 表） |
| 参照（配套旧版） | 用户级 `~/.pi/agent/npm/node_modules/@earendil-works/pi-coding-agent` | 0.99.2 | **有 `./node`**（`dist/node.js`） |

**根因**：pi 1.0.0 重构删除了 pi-agent-core 的 node 入口，pi-subagents 0.74.0（当前最新）尚未适配。上游版本断层，非本机配置错误。

### 修复选项（未执行，需用户拍板）

| 选项 | 操作 | 代价 |
|---|---|---|
| A. 降级 pi 主程序 | `npm install -g @earendil-works/pi-coding-agent@0.99.2` | 失去 1.0.0 新特性；重启 pi 生效 |
| B. 等上游 | pi-subagents 发布适配 1.0.0 的版本 | subagent 功能暂时不可用 |
| C. 绕开 | 主会话直接执行（本次审计即采用此方式） | 独立性弱于真子代理 |

### 经验教训

1. **workflow:true 失败时的正确姿势**：不要反复盲试布尔形式——先 `action:"guide"` 查文档，再改用脚本文件 + `action:"validate"` 预检（零副作用）
2. **验证 import 来源**：仓库根目录下有与包同名的目录时（如 `D:\Code\Projects\vnpy\vnpy`），`import vnpy` 会撞到本地源码而非 site-packages——验证包行为时先打印 `__file__`
3. **前台/后台 children 都走同一 runner**：本例中 async:false 不能绕开基础设施故障（文档未明说，实测发现）
